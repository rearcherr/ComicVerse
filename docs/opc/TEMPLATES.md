# OPC 轮次与交接模板

只在用户实际启动后，在 `docs/opc/cycles/<轮次>/` 使用这些模板。模板字段中的“待填写”不是证据；无需为格式而复制空报告。简小缺陷可合并为一份记录，但不能缺失需求、文件归属和验收依据。

## 1. 轮次记录：run.md

```text
轮次／状态：
用户启动指令与目标边界：
模式／最大轮数／总预算／截止条件：
产品基线版本／提交／初始工作区改动：
本轮用户任务与成功指标：
纳入需求／不做项：
证据、PRD、验证、候选、QA和反馈文件链接：
当前子任务与文件归属：
关键决策、反例、风险、下一步：
实际结束原因／已耗时／剩余预算：
交付版本和SHA256／或未交付原因：
```

## 2. 证据记录：evidence.md

```text
证据编号／问题编号：
类型：真实用户反馈／实际运行／官方资料／源码审查／假设或模拟
来源、日期、URL或本地证据路径：
涉及版本、环境、样本范围／数量：
观察原文或摘要（与推断分开）：
实际步骤、期望和实际行为（适用时）：
可信度、反例、适用限制：
是否获授权使用／是否需要匿名化：
支持或否定哪个需求／下一步验证：
```

## 3. 需求与验证：requirements.md

```text
需求编号／关联证据：
目标用户、阅读场景和痛点：
本轮价值假设／排序理由：
一句话定位／范围／不做项：
用户完成任务的主流程：
空态、错误、取消、关闭、重开和历史数据行为：
逐条验收（条件→操作→可观察结果）：
成功指标与现有基线／如何比较：
交互产物／模拟或真实用户验证结果：
技术验证、依赖、性能与存储约束：
迁移、失败恢复及回退方案：
READY判定／未通过项／leader决策：
```

## 4. 子任务交接

```text
任务编号／角色／关联需求：
输入证据和前置依赖：
目标与可观察完成条件：
唯一可写文件／共享文件owner：
本次允许的动作与预算：
结论／实际变更文件：
验证方式、实际退出码与证据路径：
风险、未覆盖、阻塞及需要谁接手：
```

## 5. 候选冻结：candidate.json／QA报告

```text
候选标识／版本／构建参数／基线提交和实际改动：
源码和工具清单manifest（路径、SHA256）：
EXE路径与SHA256／ZIP路径与SHA256：
包内EXE哈希／样例、说明与依赖清单：
开发自测及架构复核结果：
独立QA身份／是否实现过本轮产品代码：
需求→正常、边界、异常、回归场景的覆盖：
实际测试桌面／独立数据目录／命令／超时／退出码：
原始日志、截图、故障标记和故障注入的解释：
运行前后源码、工具及制品哈希是否相同：
PASS／FAIL（仅对以上指定候选）及未覆盖：
失败缺陷、修复轮次与新候选链接：
正式交付路径、时间及同制品哈希核验：
远端动作是否获授权、实际远端制品如何通过QA：
```

对于本次规范／配置变更，将 EXE／ZIP 测试项标为“不适用：未改产品”，改为规范文件清单、配置解析、角色与状态检查、最终配置候选哈希。不能填写虚构的 App 测试结果。

## 6. 反馈与下一轮：evaluation.md

```text
版本／实际交付制品：
目标指标与可比基线：
实际反馈来源、样本数、日期与授权范围：
效果状态：待反馈／已有观察／证据不足／目标达成／目标未达成（与任务DONE分开）
真实用户结果／技术回归结果／模拟预测分别是什么：
是否达到本轮目标；不能判断时缺什么证据：
新问题、反例和已否定的假设：
待办新增／调整／延期及对应证据编号：
继续条件：范围内、预算内、可验证、有合格任务：
leader决定：下一轮／研究补证／待命／阻塞及理由：
```

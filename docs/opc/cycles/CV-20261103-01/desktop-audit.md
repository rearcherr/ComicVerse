# D-01 桌面阅读状态只读审查

日期：2026-11-03（Asia/Hong_Kong）。角色：desktop_engineer。基线：v1.3.1／`3a892fd`。本次仅审查源码，未构建、运行WPF或操控用户桌面；下述反例尚不是实际运行复现。已读取角色、根AGENTS及OPC控制、流程、待办和run记录。

## 结论与优先级

建议先验证“漫画加载失败不能覆盖最后成功阅读位置”，暂缓页号直达新功能。这个反例在单页和双页都有同类状态分离缺口，与交互角色的独立走查一致；是否进入本轮开发，由leader在独立QA实测后决定。v1.3.1已修的双页分组、条漫页内自动保存及模式初始化守卫不列为当前仍有缺陷。

## E-CV-20261103-01-D01：失败目标与成功画面分离不足

类型：源码审查／未实际复现。

1. `src/ComicVerse.App/Windows/ReaderWindow.xaml.cs:498` 的`LoadPageAsync`在请求开始时就执行`_page = index`（507行）。解码失败分支（515–520行）刻意保留旧`PageImage.Source`，并仅显示“加载失败，点击重试”；`UpdateComicInfo`和`ScheduleSave`只有成功分支才执行。因此失败时可能是旧图和旧底栏、新`_page`。
2. `SaveNow`（1932行）以`_page`作为单页保存位置，没有校验此目标对应的位图是否已经显示。先前成功页的2秒保存timer、显式flush和`Window_Closing`（2092行以后）都可进入这个方法。故“正常读到页0→请求坏页2→失败→关闭”这一源码路径会把未成功呈现的页2写为阅读进度；如果坏页是最后一页，完成率可被写成100%。真实运行尚待QA确认。
3. 单页自检钩子`IsComicPageLoaded`（104行）只看`PageImage.Source is not null`，保留旧图时仍为true。新验收不能只靠此钩子判定目标页已完成；须核对加载层、图像像素/引用、页号以及DB。
4. `AddBookmark_Click`（1865行）也直接用`_page`／`_spreadStart`生成书签，未判定目标是否成功呈现。这是同一状态机制的潜在派生影响，当前不另算独立根因，需规划决定是否纳入同一验收链。

建议可观察要求：失败保留可理解的错误提示；持久化及书签不得假装已经读到未显示目标；修复后重试成功才更新画面、页号与可保存进度。保留正常异步导航和快速连续翻页能力。架构交叉复核指出仅加载守卫不充分：页0已有DB→成功读到页3但尚未过2秒防抖→页4失败→立即关闭时，简单禁止保存会丢掉成功页3，退回页0。应将请求游标与最后成功呈现快照分离；保存读取稳定快照，不仅吞失败日志或跳过全部保存。

## E-CV-20261103-01-D02：双页失败与提前完成率

类型：源码审查／未实际复现。

`RenderDoubleSpread`（806行）在开始时清空左右图像；异步过程中提前更新`_spreadStart`（825行）和`_doublePageCount`（828行）。任一图片失败时只设置“部分页面加载失败”（850–854行），成功分支才更新底栏。`SaveNow`却用当时的`_spreadStart + _doublePageCount`计算完成率；关闭或此前timer可能把未完整呈现的末组记为完成。

`IsDoubleReady`（109行）也允许任意一侧位图非空，不代表完整成功；现有`WaitDoubleLogicAuditAsync`额外检查加载层隐藏是正确的，新验收应继续核对左右位图和底栏，不只看ready。

双页失败层当前没有与单页相同的点击重试事件。可通过离开后返回模式重新触发渲染；建议如纳入PRD，沿用单页点击重试。实现上左右位图先存局部变量，全部成功且current后才原子替换呈现，失败保留旧完整组并显示明确失败目标，不能把旧图标成新组。跨模式切换也必须有明确的稳定位置来源，不能将失败请求游标传入新模式。

## 建议独立QA最小验证

只在实际App的`--smoke`增加独立fixture（由leader分配单一测试入口owner），统一走`tools/Invoke-IsolatedProcess.ps1`：

- 生成合法自有样例：一组有效PNG和一个以`.png`结尾但字节损坏的图片，置于测试目录／CBZ；不读取真实书库。
- 单页：确认正常页实际像素、底栏和DB；请求损坏的最后页，等到错误层；在窗口保持打开时等待超过2秒、显式flush、关闭重开分别核对未显示目标没有覆盖稳定进度。修复坏页并用真实重试事件验证恢复。
- 双页：先完整显示正常首组，再进入一侧损坏的末组；核对加载状态及左右图像，窗口保持打开及关闭后DB不能假装完成。覆盖RTL左右交换，避免只修左侧失败。
- 取消／竞态：请求未完成就切模式、快速跳到后续有效页以及关闭；最后完成目标的像素、底栏和DB一致，旧完成不能倒灌。未加载完即关闭但有历史进度时不得清零。
- 失败样例产生的解码日志必须精确关联fixture，不泛化忽略其他ERROR；记录桌面、超时、真实退出码、截图和最终包哈希。专项通过不能替代最终候选完整回归。

## E-CV-20261103-01-D03：页号直达实验评估

类型：源码审查／功能机会假设，暂无真实用户痛点样本。

底栏`PageInfoText`是只读TextBlock（ReaderWindow.xaml:401），`ProgressSlider`范围0–1000，不能可靠精确表达超过1000页长书中任意一页。现有`ApplySliderJump`和单页`LoadPageAsync`、条漫`ScrollToPage`、双页规范分组接口可复用，页号直达技术改动预计局部可控。需要显式1基页号→0基索引、非法/越界输入、取消、输入焦点快捷键、异步载入和双页吸附组的清晰规格。

但当前没有真实使用中的定位耗时或误差证据；不建议为运行循环而立即新增。若后续以内部导航实验纳入，须先约定例如1001页合成书中准确跳到指定页的可观察结果，并如实标记真实价值待用户反馈。本轮可靠性反例应优先。

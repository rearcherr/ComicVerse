# I-01 交互走查与候选规格

日期：2026-11-03（Asia/Hong_Kong）。角色：interaction_designer。当前为源码与流程模拟走查；没有运行 WPF、操作用户桌面、使用真实书库或开展真实用户可用性测试。本文不构成 READY 或 QA PASS。

## 本轮任务边界

优先保障既有 Windows 阅读任务：打开书籍 → 读到目标页／章节 → 导航或切换模式 → 自动保存 → 关闭重开。现有用户关于条漫捕获、排版保存及滚轮速度的反馈已有修复记录，不能重新当作仍存在的缺陷。长漫画缩略图、精确页号输入、返回跳转历史均可作为后续假设，但当前无真实查找任务耗时或错误证据，不能只因为竞品具备就进入开发。

## 现有流程及否定证据

| 任务 | 源码观察 | 交互意义／限制 |

## 待验证候选：失败页不能冒充成功阅读位置

本地发现标识 I-SRC-01（待 leader 归并正式证据编号）。类型为源码审查，未实际复现。

- 单页解码前即执行 `_page = index`；解码返回 null 时保留旧 `PageImage.Source`，不执行 `UpdateComicInfo`，只更新失败提示。
- `SaveNow` 的单页支路直接用 `_page`，且存在旧位图时不能仅凭“已有图片”判断新目标已稳定。因此可能出现画面、底栏仍是 A，而关闭或既有防抖保存把失败的 B 记入 DB。
- 双页请求先改变 `_spreadStart` 并清空两图，只有整组加载成功后才更新信息与安排保存；关闭保存是否仍写入未成功目标需要独立复现。
- 反证／限制：当前测试已有早关和模式切换守卫；不是每次失败都会自动保存（失败路径没有主动 `ScheduleSave`）。不能在无日志、DB与实际画面证据时宣称已经发生数据丢失。

建议优先用合成 fixture 复现：正常 A → 损坏 B → 正常 C，在真实 App 上核对失败期间实际画面、底栏、DB及关闭重开。若问题不存在，记录否定证据并延期；若确认，优先于缩略图等新功能。

## 候选最小交互契约（待选题确认）

用户应能区分“已读到哪里”和“正在尝试打开哪里”。只有目标内容完成适用模式的加载、实际进入视口后，才提交新的阅读位置；加载中、取消或失败不把目标当成已成功阅读的位置。

| 状态 | 可见结果 | 导航／重试 | 保存点 |
| --- | --- | --- | --- |
| 稳定 A | A 的实际内容，页号与进度一致 | 保留既有键鼠方式 | A 可防抖／关闭保存 |
| 请求 B | 保留足以识别最后成功位置的显示，提供加载提示；不能把旧 A 标成 B | 新请求可替代旧请求；关闭不被阻塞 | 不提交 B |
| B 失败 | 明确失败目标，保留最后成功位置语义；不只白屏或无声结束 | 单页沿用点击重试；是否补双页重试须由范围决定 | 最后成功位置不被 B 覆盖 |
| 重试 B 成功 | B 的内容、页号、进度同步 | 继续既有导航 | 此时可提交 B |
| 被更新请求／模式切换取消 | 旧请求不得覆盖较新的成功显示 | 当前动作生效，不弹无关取消错误 | 只保存当前模式已稳定事实 |
| 关闭重开 | 恢复最后成功阅读位置；尚未成功的请求不冒充历史 | 保留现有打开方式 | 与实际成功内容一致 |

以上是验收行为，不要求重构成特定状态机、不强加新持久化表。精确的请求页文案、双页部分成功策略与跨模式恢复边界，须在 leader 选题后结合架构、开发和 QA 确认。

## QA 场景建议

| 类别 | 场景 | 可观察判据 |
| --- | --- | --- |
| 正常 | A→B正常页，等待保存后重开 | 实际B／底栏B／DB B一致，既有完成比例不回归 |
| 边界 | 首页、末页、完整末对与混合横竖组 | 不越界，不重复末页，双页Canonical组仍与已验收行为一致 |
| 异常 | A→损坏B，失败后等待再关闭 | 不把B当成功位置；图、页号、DB解释一致，有可见错误反馈 |
| 恢复 | 修复fixture或解除暂时故障后重试B | 成功才切换内容与保存；重复重试不会提交多次错误位置 |
| 取消／加载中 | A→慢B→C，或慢B尚未落地就关闭 | B晚到不能覆盖C；关闭不把B保存成已读 |
| 模式 | 单页／双页／条漫切换中出现失败或取消 | 已成功位置语义清楚，原有模式与缩放恢复不退化；具体超出项明确未覆盖 |
| 非法输入 | 若本轮不新增输入控件，仅检查现有滑块首尾及排版非法输入回归 | 不为规格完备新增页号输入需求；现有非法排版提示不丢失 |
| 键盘 | 内容区导航，与Slider／ComboBox／TextBox／按钮获得焦点时的按键 | 内容区保留快捷键；控件保留原生编辑／激活；Esc有清楚的取消或退出语义 |

## leader 暂选后的明确规格

leader 已暂聚焦“页失败进度一致性”和“TAR兼容”，本轮不做新导航。以下对前一节候选规格作具体化；需求状态和运行复现仍由 leader／QA 确认。本角色未执行产品代码或运行验证。

### 请求位置、成功位置与历史位置

1. **请求位置**是用户希望打开的页／Canonical双页组，可用于失败后的上一页／下一页命令。它不代表已读到。
2. **本次成功位置**是实际完整进入当前模式视口的页／组，同时决定成功画面、底栏页号和新保存的位置。单页请求未成功时，不能只因旧位图非空就把请求当成功。
3. **已有历史位置**是在尚未成功展示任何内容的本次窗口中应保持的历史记录。首次加载失败／加载中立即关闭不能用默认0或未显示的新目标覆盖它；明确“重置进度”的独立用户动作仍遵守其原有合同，不在此悄悄改变。

### 单页失败与恢复

- 正常 A → 请求 B 时，可保持 A 的画面和底栏；显示加载提示。成功 B 后，再同步 B 的画面、页号和保存快照。
- B 失败时仍显示 A 及 A 的底栏；提示必须明确尝试目标，例如“第 B 页加载失败，点击重试；仍显示第 A 页”。不能只显示“加载失败”而让用户把 A 当 B。具体中文数字格式沿用项目风格。
- 点击重试只重新请求 B。重试持续失败不产生新阅读位置；重试成功才提交 B。
- 失败后按 Next 应从请求 B 的下一页 C 继续，避免基于 A 再请求同一坏 B，导致用户无法绕过损坏页；Prev 可返回 B 的前一页。画面和保存仍以最后成功结果为准。键盘、底栏按钮、点击内容翻页须遵循同一命令语义。
- 关闭时保存 A；重开恢复 A。失败期间若已先保存 A，再改缩放等会话设置，也不能顺带把 B 保存成阅读位置。
- 首次加载即失败、没有本次成功画面时，不保留无意义旧图，不用默认“1 / 1”伪装成功。显示明确目标失败及可重试／返回路径；已有历史位置不被本次失败改写。

### 双页部分失败与恢复

- 用 Canonical 双页组作为原子显示／提交单位：该组所需图片均成功后才一起更新成功画面、页号和保存位置。横页或末尾单页的组只需其适用单图成功。
- 请求新组时保留上一成功完整组；新组左／右任一图失败，不能把另一侧新图混入旧组或把半组标作完整成功。提示明确目标页范围、失败，并说明仍显示上一组。
- 提供明确重试操作，重试当前失败目标组；不要求用户猜测通过切模式才能重试。可复用既有错误覆盖区域，沿用当前 WPF 风格，无需另建弹窗。
- 第一次组加载失败且没有本次成功组时，显示空的失败状态及重试入口，不留单侧新图配默认页号来冒充可读组。
- 失败后上一组／下一组仍沿请求目标的Canonical分组移动；成功后正常保存，失败后关闭则保留上一成功组的阅读位置。

### 取消、模式与输入

- A→慢 B→C 时，B 取消或晚到不得覆盖 C。取消不提示故障，不提交 B。B 失败覆盖层也不得覆盖较新的 C 成功状态。
- 失败或加载中切模式，以最后成功位置为切换起点；无本次成功位置时保留已恢复的历史目标。旧请求不得在模式切回后晚到覆盖新位置。只改本轮缺陷相关行为，保留v1.3.1既有页内位置、缩放和RTL合同。
- 载入中可关闭；失败状态可重试、跳过或返回书架。不能为了防止坏页写进度而把整个窗口锁到不可退出。
- 此轮不新增页号文本框，因此没有新非法数字输入规则。既有滑块边界、输入焦点、排版非法输入和Esc行为属于回归。
- 重试若采用按钮，应使用原生Button焦点与Enter／Space激活；若复用点击覆盖层，需由QA记录键盘是否可达，不能声称已验证无障碍。不要为本轮临时引入与全局翻页冲突的新快捷键。

### TAR兼容的用户反馈边界

兼容修复本身沿用现有导入／打开流程；正常合法TAR应导入并读到有效图片。空包／损坏包／不支持条目仍必须有准确的导入失败或阅读错误反馈，不能把“兼容”实现为忽略所有异常或显示成功空书。具体样例和拒绝规则由Core／架构确认，QA用合成包验证；本角色不对格式读取作运行结论。

交接对象：leader、product_planner、desktop_engineer、qa_acceptance。下一步为独立复现、架构核对和READY决策；不是由本规格自行开始生产实现。

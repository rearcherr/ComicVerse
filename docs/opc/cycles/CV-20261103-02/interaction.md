## 三类位置及两个独立决策

|事实|用户语义|可用于模式入口|可用于持久化／新书签|
|---|---|---|---|
|最新有效、尚未完成的显式意图B|用户已要求前往B，尚不能声称读到|是，优先于旧成功A|否|
|已经失败的请求B|当前尝试未成功；可按目标重试或继续跳过|否；被动切模式回成功A|否|
|已成功呈现A|用户实际已看到的完整页／组／已完成恢复的条漫位置|无有效pending意图时使用|是|

模式切换是导航目标的转交；保存和书签记录已成功事实。两者不得共用一个“当前页”取值规则。修坏页不能丢掉仍有效的显式跳页，保留显式跳页也不能提前把它保存成已读。

## 导航目标合同

1. 明确用户导航（显式跳页、上一页／下一页、重试等）建立或更新最新意图。较新的明确意图取代较旧意图。
2. 连续模式切换的派生加载继承当前有效意图，不因进入新模式而把旧成功页A、初始页0或旧滚动比例提升成新意图。
3. B仍pending且未失败时，翻页→双页→条漫等连续切换继续指向B。双页加载可以规范化到包含B的Canonical组；**整组尚未成功时不得遗失原始目标B**。组成功后可按既有完整组锚点稳定提交，不扩大为永久保存原始单页锚点的新功能。
4. B已经实际失败时，撤销该失败意图的被动跨模式继承；切模式以最后成功A为起点。失败请求游标可保留给Next／Prev／Retry，避免无法跳过坏页；这些主动操作建立新的有效意图，不能继续被旧failed状态压回A。
5. 用户明确前往C后，B的取消、晚到成功或晚到失败均不能改写C，也不能清掉C的意图。模式转交时取消旧物理加载，不等于取消用户意图本身。
6. 首次条漫初始化、旧恢复回调、旧可见位置与默认0属于被动状态；它们不能覆盖有效显式B或把B误判为已成功。条漫携带B进入时不能复用无关旧savedFraction把目标拉回旧位置。

## 显示、保存、书签与关闭

- pending B期间可以保留成功A画面与成功底栏，并显示加载提示；不能把A标成B。切到没有当前成功内容的新模式时，沿用现有“上次成功位置／尚未载入”语义，不伪造新模式已成功。
- 只有适用模式的完整目标实际成功进入视口，才提交新成功快照；双页保持原子提交。失败提示明确目标，保留可重试／返回路径和上轮坏页保护。
- pending或failed期间，自动保存、立即关闭保存、新书签均使用最后成功A；无成功快照时不凭默认值新增位置或书签。已有历史位置仍按既有保护合同保留。
- 成功A尚未到防抖时间就请求慢／坏B并关闭，仍需保存A；不能仅因有pending/failed而跳过整个保存流程。
- 关闭撤销未完成加载的后续作用，保存成功A；不为完成意图阻塞退出。重新打开恢复已保存成功位置，不声称已看到未完成B。

## 可观察场景

|场景|预期结果与限制|
|---|---|
|原阻塞回归原文序列：页0成功 → 同回合首次条漫 → 翻页 → 显式页8 → 双页 → 条漫|最终真实视口包含零基页8，底栏与DB的webtoon/8及实际比例一致；原logic31的判据不修改|
|成功A → 受控慢B → 连续切模式|最终呈现B；中间尚未成功时保存／书签仍A，不能以私有cursor变化代替视口证据|
|成功A → 明确失败B → 切模式|最终目标为成功A，旧B不自动重新成为被动入口；错误恢复与上轮坏页保护同时成立|
|失败B → 显式Retry或Next C → 立即切模式|新意图有效并跨模式转交；旧失败状态不能把它拉回A|
|慢B → 显式C → B晚到成功／失败|最终C；B不得改显示、底栏、DB或新书签，不得清掉C意图|
|pending B跨双页，Canonical组包含B，未成功又切条漫|仍指向原始B；不能过早把组起点或旧成功A替代B|
|成功A尚未防抖 → pending／failed B → 立即关闭重开|DB及重开为A；成功B后才允许保存B|
|首次加载失败，无本次成功快照|没有默认0伪进度或伪书签；历史位置不被失败改写|

QA应用真实位图／视口、底栏、公开DB和重开结果验证，受控source仅用于时序／故障，不是产品文件热替换能力。现有旧logic31和新可靠性61需同时通过，不能以改期望、删失败场景或忽略某一组取得PASS。

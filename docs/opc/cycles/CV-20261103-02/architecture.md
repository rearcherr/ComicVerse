## 最小状态模型

|状态|内容及生命周期|用途|
|---|---|---|
|有效pending导航意图|generation、原始目标页，可选属于同意图的条漫fraction；显式请求产生，模式切换转交，当前失败撤销，完整成功消费|模式入口和仍有效的导航目标|
|请求游标|既有`_page`／`_spreadStart`及队列，允许指向失败目标|失败后的Next／Prev邻页、重试和现有命令累积|
|成功呈现快照|实际成功页／完整跨页、模式、比例、缩放|持久化、底栏、创建书签及无有效pending时的回退|
|初始历史目标|打开时恢复的历史页，或fromStart的0|本窗口尚无成功快照与pending时的入口；不是可直接写回的新成功事实|

无需新数据库字段、公共Core接口或大重构。保存进度的代码不读取pending意图；失败游标也不得直接作为跨模式入口。

## 交接与版本规则

1. 显式单页跳转、重试、翻页、进度条、Home／End或已解算的双页目标开始新意图。失败后Next／重试仍可按请求游标生成新意图，不会永久卡在坏页前。
2. 模式切换优先继承有效pending意图；没有pending或该请求已failed才从成功快照／初始历史创建派生入口。模式切换不是一次失败，不能因取消旧模式任务而撤销交出的意图。
3. 每个dispatch除意图generation外，仍须检查既有mode、单页load version、双页version或条漫entry epoch。转交同一意图不等于旧dispatch可以成功／失败／consume它；旧回调不得清更新意图。
4. 单页有效bitmap或完整双页所有必需bitmap成功且dispatch仍current，才提交成功快照并消费对应意图。失败只撤销仍属于自己的current意图，成功快照保持A；取消和过期不改更新状态。
5. 显式奇数页9经双页规范化时，在整组尚未成功前仍保留原始意图9；随后进入条漫应去9。只有双页真实成功后，稳定呈现锚点才可变为包含9的Canonical组起点8。
6. 条漫有pending显式页时不得用旧`savedFraction`、旧可见页0或首次初始化的旧恢复回调覆盖；可选fraction只能来自该同一意图或当前有效历史恢复。实际恢复完成且entry仍current后才消费意图。`CaptureCurrentComicPresentation`不能仅因旧条漫view已ready，就把旧视口当新目标成功。
7. 首次历史目标可以有pending意图，帮助mode转交，但尚无成功快照时关闭仍保留DB已有历史；不得把默认0或新的未呈现目标写回。fromStart同理，直到真实成功后才产生新的可保存事实。
8. 双页方向队列在实际target计算完成时开始意图；尺寸计算期间模式切换仍按原合同取消队列，本轮不引入“尚未知邻组也必须异步跨模式执行”的新能力。

- 必须原样保留并通过旧logic31：12页漫画分页0成功，同一UI回合`webtoon → paged → jump8 → double → webtoon`，最终真实视口包含8、底栏及DB为webtoon/8，且迟到旧初始化不能回灌0。

- 成功A→B已失败→切模式：以A为起点；失败目标不借pending身份跨模式复活。上轮61项坏页、失败重试、书签和防抖进度保护均必须保持。

- 奇数pending9在双页未完成时切条漫保留9；双页已完整成功时则允许按现有Canonical组锚点切换，不能混同两种状态。

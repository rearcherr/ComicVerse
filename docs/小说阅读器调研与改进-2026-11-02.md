# ComicVerse 小说阅读器专项调研与改进

日期：2026-11-02。范围：Windows 可用的本地电子书阅读软件，重点为中文 TXT／EPUB 小说体验。方法：浏览官方页面及维护者文档，并核对本项目 README、阅读器 XAML／代码、`NovelDocumentBuilder`、`NovelViewSettings` 与按书设置服务；没有安装竞品或操作桌面。下文保留调研时基线与产品建议，并单列团队最终选定范围；代码实现不能当作独立 QA 验收完成。

本文区分三类证据：**官网说明**是维护者明确声明的能力；**代码核对**是本项目可见实现；**建议／推断**是根据差距和现有架构提出的方案。未查到不等于没有，跨平台产品也不能默认所有平台功能完全相同。

## 先确认已有功能

调研时小说阅读器已经具备：

- TXT 自动编码检测和手动切换，EPUB 正文／内嵌图片解析，章节目录。
- 翻页和滚动阅读，目录跳章、进度条、章节／页位置记忆，页／章节级书签增删跳转。
- 字体、字号、行距、段间距、页边距、文字／背景色；排版按书保存，不污染其他书的默认设置。
- 滚轮加速、连续滚轮累计目标、章边界继续滚动接章，以及可调速自动滚动。
- 深浅主题、全屏及工具栏显示切换，书架在读筛选与一键继续。

所以“加目录、加字号调整、加夜间模式、加继续阅读、加全屏”都不是有效的新建议。**自动滚动也不等于文字朗读（TTS）。**

### 调研时基线的实际限制（代码核对）

| 项目 | 调研时实现 | 直接影响 |
| --- | --- | --- |
| 字号 | 12–32 WPF DIP，滑块步进标记为 1 | 大屏或低视力用户可能需要更大字号；UI 没有直接数值输入 |
| 行距 | 字号的 1.2–2.5 倍，滑块标记为 0.1 | 有调整能力，但不直观显示和输入具体倍数 |
| 段间距 | 0–24 DIP，滑块标记为 2 | 不能直接输入精确值 |
| 页边距 | 四边统一 24–120 DIP，滑块标记为 4 | 左右和上下不能分别配置，宽屏仍可能一行过长 |
| 正文 | `TextAlignment.Left`，字号至少 14 时固定首行缩进两字 | 对齐方式和缩进不能按个人习惯切换 |
| 颜色 | 若干预设下拉项 | 已有深浅配色，不应再把“支持背景色”当差距 |
| 检索 | Ctrl+F 目前用于书架书名／路径，阅读器没有书内搜索 | 无法在整本小说里快速找人名、词句或前情 |
| 书签／批注 | 数据含 `Note` 字段，但当前 UI 只提供页／章级书签 | 没有选中文字高亮、稳定文本范围批注或笔记编辑流程 |

DIP 是 WPF 的设备无关像素，不是字号的 pt；后续界面应统一单位。现有字体列表还只取系统枚举的前 200 项，是否遗漏所需中文字体需要在实际机器检查，不宜直接宣称字体缺失。

## 本轮选定范围与验收状态

团队已将本轮范围收敛为以下两项，**不是照单实现后文所有建议**：

1. **段间距和页边距精确调整。** 段间距扩展到 0–120 DIP，统一页边距设置扩展到 0–240 DIP；滑块步进为 1，并提供精确数字输入。UI、合法值校验和按书持久化须一致。翻页时实际上下边距随可用高度适当缩小，以保留可读正文区，保存的请求值不变。本轮不扩大字号或行距，也不增加独立上下／左右边距。
2. **小说正文查找。** TXT／EPUB 跨章普通字面搜索，最多显示 500 处并标明截断；展示章节和正文摘要，点击命中定位，提供上一处／下一处。F3／Shift+F3 是**正文查找窗口内**的导航快捷键，不是阅读器全局快捷键。更复杂匹配、全库索引、OCR 不在本轮。

字号范围扩展、目录过滤／章号直达、返回原位置、TTS、文本高亮批注、行宽与对齐缩进均仍为后续建议，不能写成已经交付的功能。

**当前状态：v1.3.0 最终候选三已通过独立 QA，并交付同一制品。** 验收覆盖排版 30 项、TXT 查找 16 项、基础 EPUB UI 8 项及完整隔离回归；此前候选发现的最小窗口版心和重排页号不同步问题均已修复并重新打包验收。完整 SHA256、测试证据和未覆盖项见 [独立 QA 验收记录](QA验收-v1.3.0-2026-11-02.md)。本调研本身仅依据官方材料与代码审查，不替代该最终制品的 QA 结论；复杂 EPUB、完整 CSS／竖排和 TTS 等仍不能宣称已验收。

本轮验收应特别覆盖：输入段距 0／120、边距 0／240 和非法值；立即关窗后重开恢复；大边距下阅读区布局和进度；中文跨章重复命中、500／501 处截断边界、无结果、查找取消及关窗；结果定位到匹配文本；查找窗口 F3／Shift+F3 的边界与查找进行中的行为。

## 五款 Windows 产品的官方调研

### 产品定位和格式

这些产品首先是阅读器／书库工具，不是要求用户在特定书城购买内容的客户端。部分带 OPDS、在线目录或付费同步／语音；这些扩展不应被混同为本地 TXT／EPUB 阅读的必需条件。本项目本轮不需要增建内容书城。

| 产品 | Windows 及定位 | 官方说明的相关格式／位置能力 |
| --- | --- | --- |
| calibre E-book viewer | Windows 可独立启动的阅读器，也是 calibre 书库管理器的一部分 | 官方称支持主要电子书格式；提供翻页／连续阅读、自动恢复、目录、精确位置和返回导航。[阅读器手册](https://manual.calibre-ebook.com/viewer.html) |
| Thorium Reader | EDRLab 的 Windows 10／11、macOS、Linux 阅读器，强调 EPUB 与无障碍 | EPUB 2／3、固定版式 EPUB、PDF、DAISY、有声书及 LCP 书籍；可保存位置和管理书签。[EDRLab 官方说明](https://www.edrlab.org/software/thorium-reader/) |
| FBReader for Windows | Windows 10／11 本地阅读器；另有在线目录和可选同步 | Windows 功能表列 EPUB、FB2、MOBI、RTF、DOC、纯文本、CBZ；明确不支持 PDF／DOCX 等。位置及书签可同步，跳转历史可保留。[Windows 官方功能表](https://fbreader.org/windows) |
| Koodo Reader | Windows 等平台的电子书管理与阅读器 | 官方仓库列 TXT／EPUB／PDF、无 DRM 的 MOBI／AZW3 等；阅读进度可同步，也有导出和备份。[官方仓库](https://github.com/koodo-reader/koodo-reader) |
| Readest | 有 Windows x64／ARM64 安装包的阅读器，另有其他平台与网页版 | EPUB、TXT、PDF、MOBI／AZW3 等；自动恢复阅读位置。[官方入门与格式表](https://readest.com/docs/getting-started) |

格式支持的数量不是直接的优先级依据。对本项目，先把中文 TXT／EPUB 的排版、搜索与定位做好，比同时引入多个新解析器更贴近当前需求。

**结论边界：** 五款均证明了 Windows 本地阅读工具这一市场方向；并非五款所有功能都胜过 ComicVerse。Readest 公布的行距范围与本项目一样，因此不能凭“竞品功能多”就认定现有行距上限不足。可见数值、精确输入、大字号和行宽控制是更直接的改善点。除明确列出的范围外，竞品数值输入形式与上限本次没有安装验证。

## 五项产品建议（建议／推断，不等同本轮范围）

| 优先级 | 建议 | 用户价值 | 分步方案及边界 |
| --- | --- | --- | --- |
| P1：部分本轮／部分后续 | 排版数值显示、直接输入及增减，扩大可用范围 | 用户能准确设置参数，不再盲拖滑块；适应不同屏幕 | 本轮只做段距和边距范围／数字输入。后续再评估字号 12–72 DIP、其他参数输入与增减；72 是本项目建议，不是竞品标准。行距可保留 1.2–2.5。统一 UI／校验／持久化，重排不跳回章首。 |
| P1：基础本轮／深化后续 | 书内跨章全文搜索 | 快速找人物、地名、伏笔和上次读到的句子，价值高于再堆视觉开关 | 本轮普通字面匹配、最多 500 处与截断提示、章节摘要和命中定位。返回原位置、正则或全库索引后续再做；搜索不改原文件，后台检索可取消。 |
| P2：后续 | 目录过滤、章号直达与可返回的跳转；逐步完善书签笔记 | 上千章小说不再长距离滚目录；误跳后可回原处 | 后续可先目录搜索和章号跳转，输入焦点不能被方向键翻页吞掉。书签可先编辑备注；选区高亮与文本批注须另设计章节／文本范围锚点及文件变化迁移，不应只保存易变页码。参考 calibre 位置／返回和 Koodo 目录返回。 |
| P2：短迭代 | 中文行宽与段落选项 | 宽屏行长更舒服，按习惯选择顶格或两字缩进 | 先增加左对齐／两端对齐、首行缩进 0／2 字、可选阅读最大宽度；复用已有全屏与工具栏，不重复新增“专注模式”按钮。分栏、竖排、简繁转换属于后续更大范围。 |
| P3：独立迭代 | Windows TTS 听书 | 解放视线，也为有阅读障碍的用户提供另一条路径 | 先确认本机中文系统语音可用性，设计从当前段朗读、暂停／继续、语速、换章及退出释放；缺语音时给出明确说明。句子跟读定位、睡眠定时与云端语音后续再做。不要默认上传正文，也不要把自动滚动改名为朗读。 |

### 产品建议与最终范围的区别

调研建议的主线是 **精确排版 + 基础书内搜索**，团队本轮进一步限定为前述段距／边距调整和正文查找。目录、对齐／缩进与字号扩展没有纳入本轮；TTS、文本选区批注、竖排与完整 EPUB CSS 保真仍各自成立专项，避免一次性改动阅读引擎和进度体系。

当前 EPUB 经解析块重建为 WPF `FlowDocument`，不是完整浏览器排版。故“支持任意 EPUB 原样 CSS”“竖排／ruby 完整兼容”不能当成几个设置即可完成的小功能；需要先定义目标和测试样本。

## 后续完整方案的验收重点

- **排版输入：** 中文系统小数输入、空串、非数字、越界、滚动滑块与直接输入一致；未来如扩大字号，再检查 64／72 DIP 下标题和正文不裁切；恢复同书值不改变另一本书；边输入边关闭也不丢设置。
- **重排定位：** 改字号／行距后当前文本仍在附近；滚动与翻页模式互切、异步分页完成前操作、最后一页和单屏短章均不跳章或回书首。
- **搜索：** 中文重复词、跨章命中、标点和换行、空查询、无结果、大量结果、取消／关闭窗口、换 TXT 编码后旧结果失效；点击落到匹配处，而不只打开章节首页。
- **目录与备注：** 筛选不改变原章节索引，跳转后可以回原阅读位置；书签备注保存不改书签位置，输入焦点不触发翻页。
- **格式边界：** TXT 编码可覆盖仍是本项目优势，不能为复制竞品而撤掉；扫描 PDF 没有现成文字，不把小说全文搜索承诺扩展为 OCR。

测试通过应在后续质量记录中列证据。本文完成的是官方调研和本项目代码核对，不宣称新增功能已实现或验收。
